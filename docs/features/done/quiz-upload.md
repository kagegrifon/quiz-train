# Загрузка квиза из файла

**Статус:** done

## Зачем

Пользователь может принести собственный квиз в формате JSON и пройти его в приложении —
без необходимости менять код или деплоить новую версию.

## Поведение

- На странице каталога есть кнопка **«Загрузить квиз»** — открывает `<input type="file" accept=".json">`.
- После выбора файла:
  - файл парсится и валидируется;
  - при ошибке — показывается сообщение с описанием проблемы (см. раздел «Валидация»);
  - при успехе — квиз сохраняется в localStorage и появляется в каталоге как обычная карточка.
- Загруженные квизы визуально отличаются от встроенных (бейдж «Пользовательский»).
- На карточке загруженного квиза есть кнопка **«Удалить»** — убирает квиз из каталога и localStorage.
- Если загрузить файл с тем же содержимым повторно — квиз не дублируется (id совпадёт).
- Статистика попыток ведётся так же, как для встроенных квизов (по `quizId`).

### Сценарий — загрузка

**Дано:** пользователь находится на странице каталога
**Когда:** нажимает «Загрузить квиз» и выбирает валидный JSON-файл
**Тогда:** квиз появляется в каталоге, его можно запустить

### Сценарий — ошибка

**Дано:** пользователь выбирает файл с невалидным содержимым
**Когда:** файл загружается
**Тогда:** показывается сообщение об ошибке, каталог не изменяется

### Сценарий — удаление

**Дано:** в каталоге есть загруженный квиз
**Когда:** пользователь нажимает «Удалить» на его карточке
**Тогда:** квиз исчезает из каталога и из localStorage

## Валидация

Проверки выполняются последовательно, первая упавшая возвращает ошибку:

| Проверка | Сообщение об ошибке |
|---|---|
| Файл парсится как JSON | «Файл не является валидным JSON» |
| Есть поле `title: string` (непустое) | «Отсутствует или пустое поле title» |
| Есть поле `questions: array` (непустой) | «Поле questions должно быть непустым массивом» |
| Каждый вопрос содержит обязательные поля | «Вопрос N: отсутствует поле `<field>`» |
| `mode` каждого вопроса — `"single"` или `"multi"` | «Вопрос N: недопустимое значение mode» |
  | `correctOptionIds` не пусты и ссылаются на существующие `options.id` | «Вопрос N: correctOptionIds содержит несуществующий id» |

Необязательные поля (`description`, `explainMd`, `points`) получают дефолты при отсутствии:
- `description` → `""`
- `points` → `1`
- `explainMd` → `undefined`

## Формат файла (JSON)

Файл должен соответствовать интерфейсу `Quiz` (поле `id` не обязательно — вычисляется из содержимого):

```json
{
  "title": "Мой квиз",
  "description": "Необязательное описание",
  "questions": [
    {
      "promptMd": "Что выведет `console.log(typeof null)`?",
      "mode": "single",
      "options": [
        { "id": "a", "labelMd": "`\"object\"`" },
        { "id": "b", "labelMd": "`\"null\"`" }
      ],
      "correctOptionIds": ["a"],
      "points": 1,
      "explainMd": "Исторический баг JS."
    }
  ]
}
```

## Критерии готовности

- [ ] Кнопка «Загрузить квиз» на странице каталога открывает file picker
- [ ] Валидный файл добавляет квиз в каталог и localStorage
- [ ] При повторной загрузке того же файла квиз не дублируется
- [ ] Загруженный квиз помечен бейджем «Пользовательский»
- [ ] Кнопка «Удалить» убирает квиз из каталога и localStorage
- [ ] При ошибке валидации показывается понятное сообщение
- [ ] Квиз можно пройти и увидеть статистику как обычный
- [ ] E2E-тест: загрузить файл → квиз в каталоге → пройти → удалить → квиз исчез

## Технические заметки

### Генерация id

`quizId` вычисляется как хэш от содержимого файла (поля `title` + сериализованные `questions`).
Используется FNV-1a (без crypto API — синхронно, без async).

```ts
// shared/lib/hash.ts
export function hashString(str: string): string {
  let h = 0x811c9dc5;
  for (let i = 0; i < str.length; i++) {
    h ^= str.charCodeAt(i);
    h = Math.imul(h, 0x01000193);
  }
  return (h >>> 0).toString(36);
}
```

### Хранилище загруженных квизов

Отдельный ключ в localStorage: `userQuizzes:v1` — массив `Quiz[]`.

```ts
// shared/lib/user-quiz-storage.ts
export function loadUserQuizzes(): Quiz[]
export function saveUserQuiz(quiz: Quiz): void   // upsert по id
export function deleteUserQuiz(id: string): void
```

### Каталог

`quizRegistry` (встроенные) + `loadUserQuizzes()` объединяются в `CatalogPage` при рендере.
Встроенные квизы не хранят флаг `isUserDefined` — он определяется по наличию `id` в `userQuizzes`.
