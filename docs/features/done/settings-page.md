# Страница настроек и хедер навигации

**Статус:** done

## Зачем

Каталог квизов перегружен: выбор квиза и настройки квиза на одном экране мешают друг другу.
Вынос настроек на отдельную страницу упрощает каталог и делает настройки доступными в любой момент через хедер.

## Поведение

### Каталог (`/`)

- Показывает только карточки квизов: выбор, загрузка, удаление.
- Кнопка **«Начать квиз»** запускает выбранный квиз с текущими сохранёнными настройками (из localStorage).
- Под кнопкой — краткая сводка активных настроек: например, «Таймер: 2 мин · Показывать ответы: после ответа».

### Страница настроек (`/settings`)

- Доступна из хедера в любой момент.
- Содержит все настройки квиза: таймер (вкл/выкл, время), режим reveal, показывать правильные/неправильные.
- Кнопка **«Сохранить»** — записывает настройки в localStorage и возвращает на каталог.
- Кнопка **«Сбросить»** — восстанавливает дефолтные значения (без сохранения).
- При первом открытии приложения используются дефолтные значения (см. ниже).

### Хедер

- Присутствует на всех страницах.
- Слева: название приложения / логотип (ссылка на `/`).
- Справа: две иконки-ссылки:
  - **Статистика** — иконка `IconChartBar`, ведёт на `/stats?quizId=`
  - **Настройки** — иконка `IconSettings`, ведёт на `/settings`
- Активная страница подсвечивается (иконка становится `filled` или получает `color="blue"`).

### Дефолтные значения настроек

```ts
const DEFAULT_SETTINGS: QuizSettings = {
  timerEnabled: false,
  timeLimitSec: 120,
  revealWhen: 'onFinish',
  showCorrect: true,
  showWrong: true,
};
```

## Критерии готовности

- [ ] Хедер отображается на всех страницах приложения
- [ ] Иконки в хедере ведут на `/stats` и `/settings`
- [ ] Активная страница подсвечена в хедере
- [ ] Страница `/settings` содержит все настройки квиза
- [ ] Настройки сохраняются в localStorage при нажатии «Сохранить»
- [ ] «Начать квиз» на каталоге использует сохранённые настройки
- [ ] Краткая сводка настроек видна на каталоге
- [ ] При первом запуске используются дефолтные значения
- [ ] E2E-тест: изменить таймер в настройках → вернуться в каталог → проверить сводку → запустить квиз → URL содержит верные параметры

## Технические заметки

### Хранилище настроек

Отдельный ключ, независимый от статистики:

```ts
// shared/lib/quiz-settings-storage.ts
const SETTINGS_KEY = 'quizDefaults:v1';

export function loadSettings(): QuizSettings
export function saveSettings(s: QuizSettings): void
```

`loadSettings` возвращает `DEFAULT_SETTINGS` если ключ отсутствует.

### Новый маршрут

```ts
// app/router.tsx
'/settings' → SettingsPage
```

### Хедер

```
src/widgets/app-header/
  ui/
    AppHeader.tsx
    AppHeader.module.css
  index.ts
```

`AppHeader` подключается в `AppLayout`. Использует `useRouterState` (TanStack Router) для определения активного маршрута.

### Влияние на существующий код

| Файл | Изменение |
|---|---|
| `shared/lib/quiz-settings-storage.ts` | новый файл |
| `pages/settings/` | новый слайс |
| `widgets/app-header/` | новый слайс |
| `app/router.tsx` | добавить маршрут `/settings` |
| `app/AppLayout.tsx` | подключить `AppHeader` |
| `pages/start/ui/StartPage.tsx` | убрать панель настроек, читать из storage, добавить сводку |

### Будущее: настройки per-quiz

Следующий шаг (отдельная фича): хранить настройки для каждого квиза в отдельности.
Структура хранилища тогда расширится: `quizDefaults:v1` станет глобальным фоллбэком,
а `quizSettings:<quizId>:v1` — переопределением для конкретного квиза.
Текущая реализация должна не мешать этому расширению.
