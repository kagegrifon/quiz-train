# CLAUDE.md — Quiz App

## Стек
- Vite + TypeScript + React
- `react-quiz-kit` — headless/hooks-слой состояния квиза
- `react-markdown` + синтаксическая подсветка — рендеринг вопросов с кодом
- **Mantine** — UI-компоненты (CSS Modules, без CSS-in-JS)
- **TanStack Router** — навигация между страницами
- **Playwright** — E2E-тесты в браузере

## Команды
```bash
npm run dev      # dev-сервер
npm run build    # production-сборка
npm run lint     # линтер
npm run test     # unit-тесты
npm run e2e      # E2E-тесты (Playwright)
```

## E2E-тесты (Playwright)
- Тесты размещаются в `e2e/` в корне проекта.
- Покрывать ключевые пользовательские сценарии: старт квиза, прохождение вопросов, финиш, страница результатов, статистика.
- Перед коммитом фичи, затрагивающей UI-поток, убедиться что `npm run e2e` проходит без ошибок.
- Тесты пишутся на Playwright Test (`@playwright/test`). Использовать `page.goto`, `page.click`, `page.locator`, `expect`.

## Архитектура — FSD
Проект следует Feature-Sliced Design. Подробнее: @docs/architecture.md

Ключевые правила:
- Импорты только из слоёв **ниже** своего. Слайсы одного слоя не импортируют друг друга.
- Каждый слайс экспортирует только через `index.ts` (публичный API).
- Алиас `@/` = `src/`. Использовать везде вместо относительных путей.
- `react-quiz-kit` отвечает только за состояние. Вся бизнес-логика reveal и скоринга — в нашем коде.
- Не добавлять функциональность сверх запроса. Не мокировать данные там, где ожидается реальная логика.

## Git
- Коммит после каждой логически завершённой единицы работы (фича, фикс, рефактор).
- Сообщения коммитов в формате Conventional Commits: `feat:`, `fix:`, `refactor:`, `chore:`, `docs:`.
- Коммитить только связанные изменения — не смешивать несколько несвязанных правок в одном коммите.
- Не коммитить сгенерированные файлы, артефакты сборки и `.env`.
- Ветки для фич: `feat/<название>`, для фиксов: `fix/<название>`.

## Порядок разработки (спринты)
1. UI-скелет + модель вопросов + базовая навигация. Без reveal и таймера.
2. Таймер + прогресс/очки + переход на Results.
3. Reveal правильных/неправильных + скоринг multi/single.
4. Статистика (localStorage) + UX reveal/exit.
